# API-тесты TestBoard

Автоматизированные API-тесты для сервиса [TestBoard](https://testboard.avito.com/).

Тесты написаны на **Go** с использованием библиотек `testify/suite`, `apitest` и `gjson`.

## Полезные ссылки

1. [Swagger-спецификация](https://testboard.avito.com/swagger/index.html)
2. [Техническое задание](https://docs.google.com/document/d/1IZ9SxEcePoQT6lyEmukycp1qNok4HZtok73UQnPwKSA/edit?usp=sharing)
3. [Библиотека apitest](https://github.com/steinfletcher/apitest)
4. [Библиотека gjson](https://github.com/tidwall/gjson)

## Реализованные тестовые сценарии

### 1. Создание объявлений

Позитивные проверки:

- Создание объявления с названием, описанием, ценой, количеством и фотографией.
- Получение созданного объявления по ID.
- Поиск объявления по названию.
- Проверка загруженной фотографии.
- Удаление созданного объявления.

Негативные проверки:

- Пустое название.
- Пустое описание.
- Отсутствие фотографии.
- Отрицательная цена.
- Превышение допустимой длины названия.
- Создание без авторизации.
- Создание с недействительным токеном.

### 2. Избранное

Позитивные проверки:

- Поиск объявления другого пользователя.
- Добавление объявления в избранное.
- Проверка наличия объявления в списке избранного.
- Удаление объявления из избранного.
- Проверка отсутствия объявления после удаления.
- Проверка автоматического удаления записи из избранного при удалении самого объявления владельцем.

Негативные проверки:

- Добавление несуществующего объявления.
- Добавление собственного объявления.
- Повторное добавление одного объявления.
- Добавление без авторизации.
- Удаление несуществующей записи избранного.
- Удаление из избранного без авторизации.

### 3. Дополнительные сценарии

- Поиск объявлений.
- Получение собственных объявлений.
- Проверка принадлежности объявления авторизованному пользователю.
- Проверка обязательных полей и фотографии.
- Получение собственных объявлений с недействительным токеном.

## Архитектура проекта

Проект разделён на три основных уровня:

**Client Layer** — формирование HTTP-запросов к API и получение ответов.

**Manager Layer** — обработка ответов, подготовка тестовых данных и выполнение повторно используемых операций.

**Scenario Layer** — тестовые сценарии, проверки ожидаемых результатов и очистка тестовых данных.

Основные каталоги:

```text
internal/
  client/http/
    advertisements/
    auth/
    favorites/
    myAdvertisements/
  managers/
    advertisements/
    auth/
    favorites/
    myAdvertisements/
  constants/
  helpers/
  utils/

tests/
  scenarios/
    advertisementCreation/
    advertisementSearch/
    favorites/
    myAdvertisement/

testdata/
  test_photo.png
```

## Требования для запуска

- Go — версия, совместимая с `go.mod`.
- Git.
- Доступ к серверу TestBoard.
- Тестовая учётная запись.

Для разработки можно использовать VS Code или GoLand.

## Установка проекта

Клонировать репозиторий:

```bash
git clone https://github.com/taisiya1906-dev/api-tests-student.git
cd api-tests-student
```

Установить зависимости:

```bash
go mod download
```

## Настройка окружения

Создать в корне проекта файл `.env.override`:

```dotenv
TEST_LOGIN=your_login
TEST_PASSWORD=your_password
DEBUG=false
```

`TEST_LOGIN` и `TEST_PASSWORD` — данные тестового пользователя.

`DEBUG=true` включает дополнительное логирование HTTP-запросов и ответов.

**Важно:** файл `.env.override` исключён из Git и не должен попадать в репозиторий.

## Запуск тестов

Запуск всех тестов:

```bash
go test -count=1 -v ./...
```

Запуск тестов создания объявлений:

```bash
go test -count=1 -v ./tests/scenarios/advertisementCreation
```

Запуск тестов избранного:

```bash
go test -count=1 -v ./tests/scenarios/favorites
```

Запуск тестов собственных объявлений:

```bash
go test -count=1 -v ./tests/scenarios/myAdvertisement
```

Проверка стабильности — три последовательных запуска:

```bash
go test -count=3 ./...
```

## Тестовые данные и очистка

Для позитивных сценариев создания объявлений тесты создают собственные данные и удаляют объявления после выполнения.

Для проверки операций с избранным используются два пользователя, поскольку API запрещает добавлять собственные объявления в избранное.

В текущей реализации часть сценариев регистрирует временных тестовых пользователей с уникальными адресами электронной почты.

**Ограничение:** автоматическое удаление временных учётных записей не реализовано, поскольку соответствующая операция API не подтверждена. Объявления и записи избранного очищаются тестами.

## Результаты проверок

В ходе разработки выполнены:

- Запуск всего набора API-тестов.
- Три последовательных запуска тестов избранного.
- Три последовательных запуска всех тестов проекта.
- Проверка кода с помощью `golangci-lint`.
